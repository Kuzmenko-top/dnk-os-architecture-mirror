# 📜 ADR-002: Межі та Правила Асиміляції Відкритих Рішень у DNK OS

## Статус
**Прийнято (Accepted)** — обов'язково до виконання всіма агентами та інженерами.

## Контекст
DNK OS створюється як персональна та масштабована операційна система для візуального оркестрування бізнес- та технічних процесів. У процесі досліджень було проаналізовано десятки відкритих проєктів (LangGraph, CrewAI, AutoGen, OpenDesign, Shopify AST, Open-SWE). 

Без суворих меж асиміляції виникає ризик:
1. Забруднення репозиторію чужими непідтримуваними залежностями ("Синдром Франкенштейна").
2. Ліцензійних та комерційних ризиків для власної інтелектуальної власності (IP).
3. Витоку конфіденційних даних та секретів через неконтрольовані LLM-виклики.
4. Небезпечних автономних записів на боці зовнішніх сервісів (Shopify, платіжні шлюзи).

## Рішення
1. **Канонічний код проти Досліджень**:
   * Весь виробничий код DNK OS пишеться відповідно до власних контрактів (`TaskDNA`, `DNKWorkflow`, `SCONES`, `DNKStudioWorkspace`).
   * Зовнішні репозиторії використовуються за моделлю **R3 (Pattern Adaptation)**: ми запозичуємо математику/алгоритми, але реалізуємо їх з нуля під власні Pydantic-схеми та базу даних.
2. **Human-in-the-Loop Gate (Обов'язкове схвалення людиною)**:
   * Будь-які операції модифікації (публікація в Shopify, списання коштів, створення PR у продакшн-гілку, деплой) зупиняються та очікують явного кліку користувача `[Схвалити]`.
3. **Ізоляція та безпека секретів**:
   * Жоден API-ключ не повинен потрапляти у відкритому вигляді у фронтенд-бандл.
   * Усі запити до LLM або зовнішніх API проходять через Backend Gateway (`apps/api`) з аудитом та маскуванням чутливих даних.
4. **Контроль якості (Evidence Gate)**:
   * Кожне виконання та кожен PR повинні містити машинозчитуваний пакет доказів (`evidence package`: тести, лінтинг, перевірка секретів).

## Наслідки
* **Позитивні**: Чітка архітектура, висока продуктивність, 100% захист інтелектуальної власності, відсутність технічного боргу.
* **Обмеження**: Заборонено швидке неконтрольоване "copy-paste" цілих модулів без оформлення у реєстрі асиміляції.
