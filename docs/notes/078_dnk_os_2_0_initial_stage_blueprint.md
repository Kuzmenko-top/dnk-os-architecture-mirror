## 🧭 ПИТАННЯ 1: Технологічний Open-Source Фундамент

Ми не винаходимо колесо там, де світовий open-source вже створив перевірені рішення. Ми беремо найкраще і синтезуємо в єдину монолітну систему за принципом "Один факт — один дім".

### 1.1. Агентивний Рантайм, Оркестрація та Закони
* **`nousresearch/hermes-agent`** (MIT):
  - *Що беремо*: Високошвидкісний цикл виконання інструментів, систему Pre-Tool Hooks (захист від нескінченних циклів читання), фонові процеси термінала, локальну сесійну базу SQLite FTS5.
* **`jdpolasky/chief-of-staff-2`** (MIT):
  - *Що беремо*: **13 Архітектурних Законів**, принцип Subtraction Rebuild (видалення зайвого замість накопичення мотлоху), 4-компонентну анатомію крісел агентів (`Skill`, `Source`, `Parts`, `Archive`).
* **`jdpolasky/buildbot` + `bloatbot`** (MIT):
  - *Що беремо*: Патерн розділення Будівельника (Builder) та Санітара коду (Bloat/Auditor) для автоматичного вичищення застарілих абстракцій.
* **`langchain-ai/langgraph`** (MIT):
  - *Що беремо*: Циклічні графи станів (DAG), механізм детермінованих чекпоїнтів та Time-Travel (відкат стану агента до будь-якої точки в минулому).

### 1.2. 4-Рівнева Система Пам'яті
* **`jdpolasky/ai-chief-of-staff-engine`** (MIT):
  - *Що беремо*: **Бітемпоральну пам'ять (Bitemporal Store)**. Факти мають два виміри часу: `valid_time` (коли факт був дійсним у реальному світі) та `tx_time` (коли система його записала). Це унеможливлює галюцинації при ретроспективному аналізі.
* **`DNK SCONES Engine`**:
  - *Що беремо*: Когнітивну пам'ять архітектурних рішень, інваріантів та правил із tenant-ізоляцією.
* **`Obsidian Markdown Standard`**:
  - *Що беремо*: Людиночитабельне єдине джерело правди (SSOT) через двосторонні [[wikilinks]] та стандартизовані MRH-заголовки.

### 1.3. Фронтенд, Робочий Кабінет та Просторові Полотна
* **`xyflow/xyflow` (React Flow)** (MIT):
  - *Що беремо*: Високопродуктивне нескінченне полотно, систему кастомних нод, плавні зуми та з'єднання (edges).
* **`langchain-ai/open-canvas`** (MIT):
  - *Що беремо*: Інтерфейс спільного редагування артефактів між людиною та ШІ (side-by-side: чат ліворуч, живий документ/код праворуч, історія ревізій).
* **`archify/archify`** (MIT):
  - *Що беремо*: Компілятор системних діаграм, автоматичне просторове розміщення вузлів на полотні (Auto-Layout).
* **`plannotator/artifact-server`** (MIT):
  - *Що беремо*: Механізм анотацій та Human-in-the-Loop review прямо поверх згенерованих артефактів.

### 1.4. Бекенд, Транспорт та Синхронізація
* **`tiangolo/fastapi`** + **`uvicorn`** (MIT):
  - *Що беремо*: Асинхронний бекенд, Pydantic v2 типізація, автоматична генерація OpenAPI специфікацій.
* **`DNK OCC Resolver` (Optimistic Concurrency Control)**:
  - *Що беремо*: Алгоритм 3-стороннього злиття стану графа без блокування інтерфейсу, що дозволяє користувачу і агентам редагувати полотно одночасно.

### 1.5. Маркетинг, Медіа та E-Commerce
* **`remotion-dev/remotion`**:
  - *Що беремо*: Програмний рендеринг відео через React-компоненти (генерація Reels, TikTok, продуктових креативів за мілісекунди).
* **`shopify/theme-tools` + Liquid AST Parser**:
  - *Що беремо*: Безпомилкову роботу з кодом вітрин Shopify OS 2.0 без пошкодження валідних тегів.
* **`GVCLab/PersonaLive`** (Apache 2.0):
  - *Що беремо*: Генерацію потокових інтерактивних відео-аватарів.

## 📦 ПИТАННЯ 2: Структурування Розробки та Перенос Існуючих Напрацювань

Перенос напрацювань здійснюється за протоколом **"Safe Subtraction Rebuild"** — без ламання функціоналу, але зі знищенням хаосу.

### 2.1. Цільова Архітектура Каталогів (Чистий Скелет)
```
DNK_HUB/
├── apps/                         # Точки контакту з користувачем
│   ├── api/                      # Core FastAPI Gateway (роутери, middleware)
│   └── web/                      # Visual Working Cabinet & Canvas Studio (Next.js/React)
│
├── core/                         # ЯДРО СИСТЕМИ (Engine Room)
│   ├── orchestrator/             # TaskDNA, Triage, Swarm Router
│   ├── memory/                   # 4-рівнева пам'ять (Bitemporal + SCONES + Session DB)
│   ├── resilience/               # Self-Healing Distiller, Gemini Drift Sentinel
│   ├── registry/                 # Capability Registry (каталог інструментів)
│   └── security/                 # Firewall, Token Scanner, Adversarial Review
│
├── services/                     # ДОМЕННІ СЕРВІСИ (Стандарт DNK-SRV-STD-001)
│   ├── dnk_shopify/              # Магазини, теми, чекаути
│   ├── dnk_video_ai/             # Студія відео (Remotion, аудіо)
│   ├── dnk_task_forest/          # LOD-візуалізатор задач
│   └── dnk_finance/              # Фінанси та аналітика
│
├── products/                     # ПРОДУКТИ ТА БІЗНЕСИ МАКСИМА (Ventures)
│   └── <product_slug>/           # Ізольований контур: DNA, база знань, команда
│
├── docs/                         # OBSIDIAN VAULT (Єдине Джерело Правди)
│   ├── notes/                    # База знань (000–078)
│   └── C-Suite/                  # Профілі та крісла агентів
│
├── infra/                        # ІНФРАСТРУКТУРА (Стерильний корінь!)
│   ├── docker/                   # Усі Dockerfile.*
│   ├── compose/                  # Усі docker-compose.*.yml
│   └── nginx/                    # Конфігурації серверів
│
└── scripts/                      # Детерміновані скрипти перевірки та білду
```

### 2.2. Матриця Переносу Існуючих Напрацювань (Звідки -> Куди)
| Поточний стан у DNK_HUB | Куди переносимо | Принцип обробки |
|---|---|---|
| Розрізнені 6x `Dockerfile.*` у корені | `infra/docker/` | Консолідація, видалення дублікатів |
| Розрізнені 5x `docker-compose.*` | `infra/compose/` | Приведення до єдиного стандарту мереж |
| Тимчасові `state.db`, `*.fallback.db`, логи | **ВИДАЛИТИ** | Закріпити в `.gitignore`, чистий git-статус |
| `core/orchestrator/agents/` | `core/orchestrator/` + `docs/C-Suite/` | Розділення коду виконання та інструкцій крісел |
| Сервісні скрипти розробки | `services/<service_name>/worker/` | Упаковка в стандартні сервісні пакети |
| Звіти та документація | `docs/notes/` | Додавання обов'язкових MRH-заголовків |

## ⚡ ПИТАННЯ 3: Як Має Працювати ЯДРО як Агентивна OS

Ядро DNK OS працює як **операційна система реального часу**, де:
- **Користувач (Максим)** — це CEO / Оператор високого рівня.
- **Герич Prime** — це Kernel / Архітектор процесора.
- **Сервіси** — це драйвери пристроїв та прикладні програми.
- **Агенти** — це спеціалізовані потоки виконання (threads/daemons).

### Повний Життєвий Цикл Взаємодії (Від наміру до артефакту):

```
[ МАКСИМ ] (Голос / Текст / Дія на Canvas)
    │
    ▼
[ 1. INTAKE GATEWAY ] (FastAPI + WebSocket)
    │ Фіксує подію в Сесійну Пам'ять (Session DB)
    │
    ▼
[ 2. GERYCH PRIME: TRIAGE & TASKDNA ]
    │ Оцінює складність C = F + 2D + 3S.
    │ Будує детермінований граф залежностей (DAG) з атомарними слайсами (<= 25 тулів).
    │
    ▼
[ 3. 4-TIER CONTEXT HYDRATION ]
    │ Довготривала: тягне правила та архітектурні обмеження з SCONES / Bitemporal.
    │ Проєктна: тягне специфіку бренду з products/<slug>/PRODUCT_DNA.md.
    │ Сервісна: тягне схеми необхідних сервісів з Capability Registry.
    │
    ▼
[ 4. SWARM EXECUTION ENGINE ]
    │ Герич Prime паралельно диспатчить агентів (через dnk_swarm_parallel):
    │ • dnk_dev_fullstack -> генерує роутери та логіку
    │ • gerych_builder -> створює компоненти на Canvas
    │ • dnk_shopify / dnk_video_ai -> генерують бізнес-артефакти
    │
    ▼
[ 5. BIDIRECTIONAL STREAMING & OCC MERGE ]
    │ Всі зміни через WebSocket транслюються на візуальне полотно користувача наживо.
    │ Будь-які одночасні правки Максима та Агента зливаються через OCC без конфліктів.
    │
    ▼
[ 6. ADVERSARIAL AUDIT GATE & SELF-HEALING ]
    │ gerych_auditor перевіряє якість.
    │ При збої: автоматичний пошук рішення через Distiller -> авто-виправлення.
    │
    ▼
[ 7. ARTIFACT & KNOWLEDGE COMMIT ]
    │ Зелений результат затверджується.
    │ Нове знання записується в Obsidian та довготривалу пам'ять.
```
