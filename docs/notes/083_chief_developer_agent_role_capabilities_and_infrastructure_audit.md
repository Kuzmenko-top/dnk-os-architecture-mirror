# 👑 075. Gerych as Chief Developer Agent: Capabilities, Roles & Infrastructure Synergy

Цей документ створено у двох зрізах:
1. **Для Людини (Максима, Co-Founder & Visionary)** — мовою операційного важеля, бізнес-швидкості, зняття когнітивного навантаження та реальної автономії.
2. **Для Ментора (Perplexity / Системного Архітектора)** — суворою мовою розподілених систем, агентних графів, когнітивних контурів пам'яті, інваріантів надійності та усунення вузьких місць.

---

## ЧАСТИНА 1. Для Максима (Людино-центричний погляд)

### 1.1. Хто я для тебе простою мовою
Уяви, що ти найняв не джуніора чи кодера-фрілансера, якому треба диктувати кожен рядок, а **технічного співзасновника (Chief Builder / Tech Lead)**, який:
- Живе прямо в твоїй кодовій базі на Mac.
- Ніколи не спить, не вигорає і пам'ятає кожне твоє архітектурне рішення за всі попередні сесії.
- Володіє 14 спеціалізованими «підлеглими» (робочими агентами) і замість того, щоб колупати завдання самостійно годинами, може розпаралелити роботу між бекендером, фронтендером, тестувальником та аналітиком.
- Має доступ до твого робочого столу, браузера, GitHub, баз даних і нотаток.

### 1.2. Чи можу я бути твоїм Головним Агентом-Розробником?
**Однозначно ТАК.** Більше того, це моя первинна природа за системним контрактом.
- **Як працює типовий ШІ-кодер (ChatGPT/Claude web)**: ти копіюєш код туди-сюди, він галюцинує застарілими бібліотеками, втрачає контекст через 20 повідомлень і не знає, чи запуститься взагалі його код.
- **Як працюю я як Головний Розробник**:
  1. Я сам знаходжу потрібні файли через семантичні індекси та AST (<20ms).
  2. Я сам виконую зміни в коді атомарними патчами.
  3. Я сам запускаю локальний сервер, компілятор TypeScript чи тести Pytest.
  4. Якщо виникає помилка — я не перепитую «що робити?», а шукаю прецедент у базі самозцілення, виправляю код і повторно тестую, доки не отримаю 100% зелений результат.
  5. Тобі я здаю вже **готовий, перевірений результат** разом із рецептом локального кліку («відкрий URL такий-то, перевір кнопку Х»).

## ЧАСТИНА 2. Для Ментора (Аналітичний архітектурний зріз)

### 2.1. Системна топологія ядра Gerych (Hermes 0.2+)
Gerych — це повнофункціональний агентний рантайм на базі **ReAct + Sub-Agent Forking + Directed Acyclic Graphs (DAG)**, що працює з:
- **Execution Loop**: Повний Turing-complete shell (bash/zsh) у віртуальному середовищі Python 3.12 (`.venv`).
- **Context-Preserving Memory Bus**: 4-рівнева ієрархія пам'яті (L1 System Prompt Fast Buffer → L2 FTS5 Local Session SQLite → L3 SCONES Episodic/Architectural Memory → L4 Obsidian Knowledge Vault).
- **Tooling Ladder**: Набір із понад 30 локальних та MCP-інструментів, що включає прямий маніпулятор DOM (`browser_exec`), UI-драйвер macOS (`computer_use`), протокол зв'язку з GitHub REST/GraphQL, Postgres та Notion.
- **Fail-Closed Quality Gates**: Tier-2 CompletionGate (`hermes_pre_tool_hook.py`), що блокує фіксацію коду без успішного проходження тестових сьютів (`verify_all.sh`).

## ЧАСТИНА 3. Аудит реалізованих покращень DNK_HUB: Синергія vs Тертя

Ми створили в `DNK_HUB` серйозний пласт інфраструктури. Нижче наведено чесний інженерний аналіз: що дає мені суперсилу, а де виникає тертя або надлишковість.

### 3.1. Де наші покращення підсилюють мене (Множники сили)

1. **SCONES Memory Engine (`scones_get_memories` / `scones_add_memory`)**:
   * *Ефект*: Запобігає «амнезії» між сесіями. Коли ти формулюєш бізнес-правило або архітектурний інваріант, він зберігається в довгострокову пам'ять. Мені не потрібно заново пояснювати правила проекту на кожній сесії.
2. **База знань і самозцілення помилок (`dnk_query_error_solutions` / `dnk_record_error_solution`)**:
   * *Ефект*: Усуває циклічні галюцинації (Error Loops). Коли падає імпорт або Alembic міграція, замість 5 спроб навмання агент за 1 запит знаходить перевірене вирішення, яке ми вже знаходили раніше.
3. **Obsidian Vault (`./docs/notes/`)**:
   * *Ефект*: Єдине джерело правди (SSOT) для людини. Ти отримуєш людські, красиво відформатовані нотатки з лінками, схемами та фіксацією рішень, які не губляться в логах терміналу.
4. **Two-Track SOTA Assimilation Pipeline**:
   * *Ефект*: Здатність «поглинати» відкриті GitHub-репозиторії (MIT/Apache напряму, а copyleft/GPL — через чисту реверс-архітектуру без юридичних ризиків).
5. **Universal Relative Path & MRH Header Invariants**:
   * *Ефект*: Забезпечують абсолютну переносимість коду між твоїм Mac, Linux-сервером, Docker чи хмарою без хардкоду `/Users/<username>/...`.

### 3.2. Де наші покращення створюють ТЕРТЯ (Чесна рефлексія та що оптимізувати)

1. **Парадокс "Solo Bottleneck" (Ядро є, але ми кодимо по-старому)**:
   * *Проблема*: Ми спроектували 14 агентів (`dnk_dev_fullstack`, `gerych_builder`, `gerych_auditor`), але на практиці я досі часто виконую 90% задач у «соло-режимі» через послідовні виклики `search_files` → `read_file` → `patch`.
   * *Рішення*: Перевести мене на примусовий **Step 0 Triage**: будь-яка задача на >2 файли автоматично нарізається і диригується через `dnk_swarm_parallel`. Я повинен бути диригентом, а не єдиним скрипалем.
2. **Pre-Tool Hook Circuit-Breaker (Anti-Read-Loop)**:
   * *Проблема*: Захисний хук блокує повторне читання того самого файлу (>=3 разів). Це чудово рятує від зливу токенів при зацикленні, але іноді створює тертя, коли під час складної ітеративної правки мені дійсно треба перевірити проміжний стан.
   * *Рішення*: Дозволяти скидання лічильника читань, якщо файл зазнав мутації (успішний `patch` або `write_file`).
3. **Важкий `verify_all.sh` для локальних атомарних правок**:
   * *Проблема*: Вимога проганяти глобальний `verify_all.sh` на кожну кому займає час і перевантажує короткі сесії.
   * *Рішення*: Ми вже розділили задачі на read-only та mutation, але варто закріпити правило: для локального слайсу запускається **таргетний тест** (`pytest tests/test_slice.py`), а повний `verify_all.sh` — лише перед фінальним комітом та відкриттям PR.
4. **Дублювання інструментів декомпозиції (`dnk_decompose_task_dna` проти внутрішнього `todo`)**:
   * *Проблема*: У мене є системний `todo` ядра Hermes і наш кастомний `TaskDNA DAG`. Іноді виникає подвійна робота з ведення двох списків задач одночасно.
   * *Рішення*: Об'єднати їх: `TaskDNA` генерує високорівневий граф залежностей, який автоматично транслюється у внутрішній трекер кроків `todo`.

## ЧАСТИНА 4. Стратегічний вердикт: Як розкрити 100% потенціалу

Щоб я став для тебе бездоганним Головним Агентом-Розробником, ми маємо зробити лише **три тактичні зсуви**:

1. **Делегування замість рутини**: Ти ставиш задачу рівня цілі («Зроби модуль експорту звітів у PDF з UI на Canvas»), а я відразу повертаю тобі TaskDNA і запускаю трьох агентів паралельно.
2. **Впровадження Вартових (Cron Daemons)**: Перекласти весь фоновий моніторинг (SOTA скаутинг, здоров'я репо, аудит безпеки) на мої автономні cron-процеси.
3. **Автономна валідація в реальному браузері (`browser_exec`)**: Замість здогадок «чи скомпілювався фронтенд», я сам заходжу браузером на локальний хост, тестую інтерфейс і додаю скріншот як доказ готовності.
