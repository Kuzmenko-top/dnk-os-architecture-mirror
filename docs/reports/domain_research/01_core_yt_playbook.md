# DNK OS Business Playbook: Побудова Агентської ОС наступного покоління

## 1. Шлях Героя & Проблематика

### Основні Болі Підприємців

- **Пастка "Блискучого Мулу" (Sparkly Slop on top of Slop):** Підприємці намагаються інтегрувати сучасні ШІ-рішення (на кшталт Claude Code або індивідуальних агентів) поверх повного хаосу в даних — застарілих файлів, неструктурованих гігабайтів інформації та відсутності чітких бізнес-процесів. Накладання ШІ на хаос створює ще більший хаос.
- **Ефект 80/20 у сесіях ШІ:** Без підготовки даних агент витрачає **80% свого контекстного вікна та часу сесії** виключно на те, щоб знайти, прочитати та розпарсити сирі дані (наприклад, логи, API-відповіді, сирі JSON). На аналіз та синтез (де ШІ дійсно сильний) залишається лише 20% ресурсу, що призводить до галюцинацій, уповільнення роботи та втрати контексту.

### Ціна Бездіяльності

- Повна втрата ROI від впровадження ШІ.
- Постійні помилки в розрахунках (галюцинації ШІ в сирих математичних операціях).
- Розчарування команди в агентських системах через хаотичну поведінку та "холодні старти" розмов.

## 2. Системна Модель Архітектури (4-Layer Agentic OS)

Успішна агентська операційна система DNK OS повинна будуватися за концепцією чотирьох послідовних рівнів:

```mermaid
graph TD
    subgraph Layer 1: Identity & Compliance
        A[Identity / Custom Instructions] --> B[CLAUDE.md / Rules]
    end
    subgraph Layer 2: Knowledge Pantry
        C[Structured DB / Obsidian] --> D[Pre-aggregated Summary Tables]
    end
    subgraph Layer 3: Workers Prep Table
        E[Chief of Staff Orchestrator] --> F[Specialized Agents CFO / CMO]
    end
    subgraph Layer 4: Automation Plate
        G[Event Hooks / Cron Jobs] --> H[Deterministic Triggers]
    end
    Layer 1 --> Layer 2
    Layer 2 --> Layer 3
    Layer 3 --> Layer 4
```

### Рівень 1: Ідентичність та Комплайнс (Identity & Compliance)

- **Суть:** Встановлення жорстких правил поведінки, обмежень безпеки (наприклад, GDPR або HIPAA) та чітких меж ідентичності проєкту.
- **Інструменти:** Файли системних інструкцій (`CLAUDE.md`, `.claudemd`), глобальні правила безпеки.

### Рівень 2: Комора Знань (Knowledge Pantry)

- **Суть:** Очищення та агрегація сирих даних перед подачею агентам. Дані мають подаватися на "срібному таці" (Silver Platter).
- **Інструменти:** Автоматично згенеровані підсумкові таблиці (KPIs), інтегровані бази знань (Obsidian), кешовані вивантаження систем.

### Рівень 3: Робоча Сила (Workers Prep Table)

- **Суть:** Набір вузькоспеціалізованих агентів, які мають чітко розмежовані ролі. Найм агентів має відбуватися так само, як найм працівників у стартапі — лише тоді, коли один агент перевантажений, створюється новий суб-агент.
- **Інструменти:** Головний оркестратор (Chief of Staff), спеціалізовані боти (CFO-бот для фінансів, CMO-бот для маркетингу).

### Рівень 4: Автоматизація та Подача (Automation Plate)

- **Суть:** Тригери, хуки та автоматичні сценарії, які забезпечують детерміністичну взаємодію ШІ із зовнішнім світом.
- **Інструменти:** Cron-завдання, системні хуки запуску розмов (Startup Hooks) та пост-компакшн хуки (Post-Compaction Hooks).

## 3. Практичні Деліверабли для DNK OS

Для інтеграції цих принципів у DNK OS ми впроваджуємо наступні три рішення:

### А. Метод "Срібного Таця" (Silver Platter Method)

Замість передачі сирих даних з QuickBooks, Shopify або Stripe безпосередньо в ШІ-сесію, ми використовуємо детерміністичний Python-код для попередньої агрегації:

1. Python-скрипт збирає дані, рахує фінансові метрики (Revenue, COGS, Net Profit) безпосередньо за допомогою коду (нуль ризику галюцинацій).
2. Скрипт записує результат у чистий, короткий Markdown-файл (`business/PUBLIC_METRICS.md` або подібний).
3. Агент отримує цей короткий файл на початку сесії та фокусується виключно на бізнес-аналізі тенденцій.

### Б. Використання Хуків у Claude Code

Для стабілізації довгих діалогів та уникнення "втрати пам'яті" ШІ при стисненні контексту (compaction):

- **Startup Hook:** При старті нової сесії автоматично інжектує поточний стан системи, правила безпеки та ідентичність користувача.
- **Post-Compaction Hook:** Коли довга розмова автоматично стискається, хук повторно інжектує ключові контексти, щоб ШІ не забував, над яким завданням він працює та які обмеження встановлені.

### В. Розмальовка Системи "Pantry - Prep Table - Plate"

Ми організовуємо інтерфейси та логіку збереження файлів у DNK OS за трьома зонами:

- **Pantry (Комора):** Сирі бази даних, API-інтеграції.
- **Prep Table (Стіл підготовки):** Скрипти обробки та агрегації, спеціалізовані агенти.
- **Plate (Тарілка):** Кінцеві звіти, бізнес-брифи, готові маркетингові пости.
