# 🌲 Констиутуція та Головний Навігатор Документації DNK OS

Ласкаво просимо до канонічного простору документації DNK OS MVP. Всі документи структуровано відповідно до суворих гігієнічних та архітектурних регламентів.

---

## 📂 Структура Каталогів `docs/`

- **`tasks/`** — Канонічний простір садівництва Task Forest. Завдання розділені за шкалою рослинності.
- **`tech/`** — Технічні специфікації (`SPEC_`), стандарти розробки (`STD_`), архітектурні плани (`ARCH_`), та когнітивні логи (`LOG_`).
- **`reports/`** — Офіційні звіти виконання, звіти циклів (`execution_cycles/`), та аудит-логи.
- **`schemas/`** — JSON, YAML та GraphQL схеми даних системи.

---

## 🌿 5 Рівнів Таксономії Task Forest (`tasks/`)

Всі завдання та дорожні карти у системі описуються за допомогою п'ятиорганічної шкали:

1.  **🌾 01_Fields (Рівень 1)** — Глобальний проект чи великий реліз продукту.
2.  **🏞️ 02_Sectors (Рівень 2)** — Сектор, підсистема або великий технологічний домен.
3.  **🌳 03_Trees (Рівень 3)** — Епік або архітектурна група фіч. Генерує звітність циклу (Cycle Reports).
4.  **🌿 04_Bushes (Рівень 4)** — Окрема фіча, на якій виконується каскадний ролап (Cascade Rollup).
5.  **🌸 05_Flowers (Рівень 5)** — Атомарна інженерна таска, призначена ройовим агентам.

---

## ⚡ Технічні Префікси в `tech/`

Для повної навігаційної прозорості всі технічні файли впорядковані за префіксами:
- **`ARCH_`** — Архітектурні креслення та плани розвитку.
- **`STD_`** — Інженерні стандарти, регламенти та правила безпеки (наприклад, Zero-Host).
- **`RUNBOOK_`** — Інструкції з розгортання, інтеграції та конфігурування сторонніх API.
- **`SPEC_`** — Специфікації поведінки, протоколів та реєстри паттернів.
- **`CATALOG_`** — Індекси знань, донорів та завантажених технологій.
- **`LOG_`** — Когнітивні логи рефлексії та результати навчання.
